## Naming and upgrade behavior

The product, supported source, deployment service, examples and CI names use `hob` / `HOB_*`. Old names remain only for migration, defensive secret filtering, historical source/volume references and migration tests. Supplied audit filenames, private operator configuration, third-party reference trees, and this IDE checkout's directory name are not rewritten.

`server/hob-config.mjs` migrates old environment names without overriding canonical values and moves a single local legacy data directory without losing contents. Ambiguous dual directories stop startup. Browser preference migration preserves canonical values and tolerates disabled storage. Both have regressions. Cookie renaming requires a new login. Existing Coolify secrets must be copied into the new generated-variable names, and its proxy assigned to `hob`; see [the concrete upgrade procedure](../deploy/COOLIFY.md#upgrade-to-the-hob-namespace).

## Runtime ownership and recovery

The pinned runtime remains Hermes commit `7e9eb8d9a30f4a9bb9f8ecaf816b4b0ffdf47357`. The application adds a checksum-qualified native JSON router for schedule previews and proposal reviews, alongside the heartbeat, timezone-cache and selected-page browser evaluation fixes. Every qualified source hash must match at image build; unknown upstream content fails the build. A complete image rebuild is required.

The review extension reads the native pending store and delegates application to native memory/skill appliers with their preconditions. Decisions claim a proposal before applying it. A crash, audit failure or unconfirmed native result leaves an unresolved claim; another request cannot blindly apply it again. The queue exposes complete retained proposals. After inspecting current native state, an operator can record observed application or abandonment. Both persist a distinct `operator_reconciled` event and clear the claim without applying, retrying or undoing anything. Decision history is metadata, not automatic rollback. Preserve native state, claims and audit together. The audit is not an independently tamper-proof security boundary against a process with the same filesystem identity.

Delivery recovery observes retained native terminal receipts in bounded batches; it never resubmits a turn. Expired receipts cannot manufacture results or erase a known terminal outcome. Publication keeps original files, requires independent bounded files under assigned roots, and uses atomic destination links to avoid overwriting a different artifact. Workspace files and private receipt metadata must be backed up together. The file format/path allowlist is not a general secret-classification system.

## Open acceptance and implementation scope

Docker is unavailable locally. [Linux image CI at `dcf045bb`](https://github.com/abdlx/hob/actions/runs/40931015172) passed web/server validation and both shared and OS-user-isolated image runs. The image checks cover native review/preview APIs, actual image input at the fixture provider, artifacts and scoped downloads, ACLs, proactive scheduling/relay/heartbeat, container crash/recreation, and the baked checkout SHA. All inference in these image tests uses the owned local fixture provider; no live vendor quality or latency result is claimed.

Both deployment modes pass actual background-memory staging, complete payload inspection, cross-bot/stale denial, approve/reject/idempotency, and persisted approved/absent rejected memory after recreation. A real conflicting skill-create approval retains an unconfirmed claim outside the queue. That claim survives recreation, denies another bot's access, supports idempotent operator abandonment, and preserves the active skill.

The native browser check reproduced a concrete integration error: navigation reached the requested page, but console evaluation reported `chrome://new-tab-page/` through its optional supervisor fast path. The supervisor independently selected the first page before navigation. A fourth checksum-qualified correction keeps evaluation on Hermes's existing selected CLI session whenever a supplied CDP endpoint is configured; other native browser modes retain their existing fast path. A separate HOB polling fix applies the viewer's target-selection rules without an open viewer, so a launch tab cannot hide the work page.

The shared image now passes the focused real-Hermes tool scenario as its unprivileged runtime user, with a separate disposable HOB broker and Hermes home. It verifies same-page navigation/evaluation, snapshots, ref-based typing/clicking, raw CDP refusal, human takeover, unchanged DOM after denied mutations, fresh refs after handback, and successful resumed input. It submits no model calls or external form actions. This qualifies the exercised native tool-to-broker path; it is not an expanded browser capability benchmark or latency claim. The isolated image separately passes its filesystem, process, browser-UID and recreation checks.

The pinned native clock previously cached a profile's timezone by config path alone. The checksum-qualified fix keys the bounded cache by the effective zone and uses one coherent resolved value. Both image modes pass immediate timezone changes, spring/autumn daily cron, an autumn repeated hour, elapsed intervals, and a spring skipped-time instant. Reference-date previews use Hermes's own `compute_next_run`; saves still validate from the current native clock. The UI formats previews in the bot's zone.

`deploy/live-acceptance.mjs` makes the live front-door checks reproducible using an in-memory/environment password. It never starts a conversation, model/tool call or valid job, changes configuration, or returns private payloads in its report. A proxy 404 stops the audit before login; a failed login leaves cookie/authenticated checks untested rather than fabricating security failures.

Performance diagnostics now record native HTTP/RPC duration, native admission and settlement, time to the first streamed token, browser cold/warm start, lease/challenge wait, mutating-command acknowledgement, and artifact publication. Samples and disk retention are bounded; the authenticated `/api/hermes/diagnostics/performance?profile=...` endpoint checks enrollment and returns only that bot's samples. Traces hash native admission IDs and exclude prompts, credentials, URLs, page content, filenames, parameters and raw errors. p50/p95/max include recorded failure/unknown outcomes. Browser CDP spans remain bot-scoped because the CDP transport carries no native admission ID; no exact concurrent-run attribution is invented. These are HOB boundary timings, not provider-internal model/tool/cost spans or production latency commitments.

Native model-turn and wall-clock limits are configurable per bot. An aggregate hard currency cap across provider, tool, background and delegated calls is **not implemented**; the UI says so. Release scope requiring that cap remains open. The pinned runtime's auxiliary-call hooks are observer-only, fail open and ignore return values; they cannot safely reserve or reject spending. See [the pinned contract](https://github.com/NousResearch/hermes-agent/blob/7e9eb8d9a30f4a9bb9f8ecaf816b4b0ffdf47357/agent/auxiliary_hooks.py). A complete cap needs an authoritative fail-closed reservation/accounting contract covering all billed call paths, not a dashboard estimate or an observer plugin. Repeated real-provider latency/cost and optimization targets remain unverified.

The generated report is local/private; supplied prompts and answers are not republished in the repository.
